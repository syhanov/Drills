Копия массива

Открой app.js. Стенд уже показывает данные; девять опытов ты пишешь сам. Сначала запиши предсказания в оставленном комментарии, затем запускай код и допиши объяснения.

  1. Сравни три способа получить copy: ссылка copy = source, копия массива copy = [...source], массив поверхностных копий объектов copy = source.map(item => ({ ...item })).
  2. Для каждого способа проведи три отдельных опыта: отсортируй copy по id по возрастанию; присвой copy[0].name = "Changed"; добавь "new" в copy[0].tags.
  3. Перед каждым из девяти опытов заново вызови createItems() для source. Не продолжай изменения после прошлого опыта: иначе индекс 0 может обозначать уже другой объект.
  4. До операции сохрани снимок через JSON.stringify(source). После операции выведи через report("Подпись", значение) снимки, массивы id, имена и метки обоих массивов. Объясни, что общее на уровнях «массив → объект → tags».
  5. Напиши sortedById(items): верни новый массив, отсортированный по id, не меняя исходный массив и объекты. Объясни, почему для одной сортировки не нужна глубокая копия.

Границы и конкретные значения

  • В каждом свежем входе порядок id — [3, 1, 2], имена — ["Cedar", "Aster", "Birch"], метки — [["green"], ["red", "blue"], []].
  • После сортировки порядок copy — [1, 2, 3]. После отдельного изменения имени имена copy — ["Changed", "Aster", "Birch"]. После отдельного добавления метки copy[0].tags — ["green", "new"].
  • Меняется ли при каждом опыте source — твоя часть предсказания и объяснения, не готовый ответ стенда.
  • sortedById(createItems()) даёт id [1, 2, 3], исходные id остаются [3, 1, 2]. Для [] функция возвращает новый пустой массив.
